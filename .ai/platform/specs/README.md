# Specs

One file per non-trivial feature, named `{YYYY-MM-DD}-{kebab-title}.md`, written **before**
the work. Small fixes skip this.

A spec states the problem, the chosen approach and what was rejected, the affected API and
UI paths, and the tests that must ship with it. It carries a changelog as the feature
evolves, so the reasoning survives the commit that implemented it.

Check here for an existing spec before modifying anything non-trivial.
